# 互联通道：能创造什么需求、给用户什么心智（2026-11-16）

> 配套 [`INTEROP-APIS.md`](INTEROP-APIS.md)（有哪些 API）与 [`../entry/src/main/ets/common/Interop.ets`](../entry/src/main/ets/common/Interop.ets)（已实现的通道）。
> 这份文档回答的是另一件事：**这些通道拿来干什么，用户凭什么记住它。**

---

## 0. 一句话

**不是「加了几条通信能力」，而是「这个 App 从此不只是你一个人的记事本」。**

一个只跟自己说话的工具，心智是「工具」；一旦能把一段对话、一个文件、一条结论**递给旁边的人**，
心智就变成「桌面」——你会习惯性把东西往这儿放，因为它能递出去。

---

## 1. 三条真通道，三个不同心智

### A. 同一 WiFi 直连 → 「递手机」的数字化

**用户场景**：两个人坐在一起，一个让 AI 出了份方案/行程/报错解释，想给另一个看。
今天怎么做：截图发微信、或者把手机递过去。
有了 LAN 直连：**对面那人打开同一个 App，点「加入」，立刻在自己手机上看到全文**，还能接着改。

**心智**：*我们家/我们组的 App 能互相说话*。不需要登录、不需要加好友、不需要服务器。
这是所有方案里**唯一「断开网络也能用」**的——两个人在山上、在飞机上、在没有 SIM 的旧手机上，只要连同一个热点。

**它创造的新需求**：
- 「把这段对话转给他」变成一次点击，而不是截图→发送→对方看图→看不清→再问
- 两台设备**共享同一个工作区的一瞬**：一个人跑出来的文件，另一个人直接打开
- 离线场景：露营、考试复习、无网会议室

### B. 中继服务器 → 「发链接」的对话版

**用户场景**：人不在旁边。想把这轮排查过程/这份方案给他。
今天怎么做：导出 Markdown → 发文件；或者干脆讲一遍。
有了中继：**生成一个房间，把房间号发过去，对方打开 App 进来就能看到实时更新**。

**心智**：*这个 App 里的东西可以「直播」给别人看*。
和 dsh-go 的「对话回放链接」是同一个需求，但我们的形态是**实时的**，不是事后快照。

**它创造的新需求**：
- 远程协助：对方看着你手机的对话实时跟读，"你往上翻一点"
- 多人围观一次 Agent 运行（评审、教学）
- 跨端接力：手机上开个头，电脑上接着聊（同一房间）

### C. 剪贴板 → 「手动但零门槛」的兜底

**用户场景**：只想把地址/一段结论挪到别的地方。
**心智**：*没有连接也能传*。它的价值不是快，是**永远可用**——没网、对方没装 App、对方是微信，都能用。

## 2. 暂缓的四条，以及为什么「先摆出来但不做深」

| 通道 | 心智设想 | 为什么先不做深 |
|---|---|---|
| **同账号设备**（`distributedDataObject`） | 「我的手机和我平板是同一台」 | 只覆盖自己的设备，**不是和人通信**；而且华为账号体系要用户先登录，跟「不联网也能用」的定位冲突 |
| **蓝牙 BLE/SPP** | 「碰一碰就传」 | 双方都要装 App + 十米内 + 配对流程，**比 LAN 直连没有任何优势**，只多了权限和失败模式 |
| **星闪 NearLink** | 同上，更快 | 机型覆盖少；等有明确场景再开 |
| **RPC / DataShare** | 「别的 App 能读我的对话」 | 需要对方是特定提供方/服务，现实里没有这样的 App；开放数据出去风险大于收益 |

这四条**代码里已经有接口和能力查询**（`probeChannels()` 会如实报告设备支不支持），
面板上灰着显示原因——**让用户知道"这个我们想过，只是现在没开"，而不是"它不支持"**。

---

## 3. 产品上必须守住的四条

1. **不假装有账号体系**。LAN 直连就是「你把地址给我」，没有好友、没有通讯录。加了反而要解释一堆。
2. **默认不监听**。开房间是明确动作，退出面板就关。一个聊天 App 在后台开着端口是不负责任的。
3. **收到的东西不自动进对话**。先显示在互联面板的日志里，用户点了才用。别人的文字不能直接变成我的 prompt——这是注入面。
4. **说清楚"对方能看到什么"**。面板顶部一行写「同一 WiFi 直接连，不需要账号」——用户要知道这条线没有中间人，也没有加密（LAN 是明文 TCP）。加密要么一开始就说，要么一开始就别说安全。

---

## 4. 已在代码里的形态（这一版的边界）

- `common/Interop.ets`：统一信封（`{v,id,from,at,text}`，换行分帧）+ `LanChannel`（host/join/send）+ `WebSocketChannel` + `ClipboardChannel` + `probeChannels()`
- `view/InteropSheet.ets`：设置页 ›「互联」展开——本机地址、开房间、加入、连中继、发消息、消息日志、通道能力清单
- **只做一对一**：一个房间一个客人。多人需要身份与转发，那是 B 路线（中继）的事。
- **不做加密**：LAN 是明文 TCP。要加密就得先有身份，而身份正是我们现在没有的。

## 5. 下一步（按价值排序）

1. **收到的消息一键「放进对话」**——把互联和 Agent 接起来，这是整件事的价值闭包
2. **房间码而不是 IP**——`192.168.1.5:4518` 对人不友好；二维码/短码是体验分水岭
3. **中继服务最小版**——几十行 WebSocket 转发，跨网络才成立
4. **两台设备互发文件的通道**——复用同一信封，加 `kind:'file'` 与分片
