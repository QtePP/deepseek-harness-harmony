# 复盘

## 输入

- 用户口述：结果、我方阵容、关键节点。
- 或战绩截图：用 `read_image` 读，只取画面里确实有的数字。
- 历史：`data/matches/*.json`，文件名按 `<日期>-<序号>` 排序，只读最近 5 个。

## 步骤

1. **先读历史**，找重复出现的模式。连续三局同一个死法才算模式；单局只当偶然，明说"样本不够"。
2. **写一条新记录**：`data/matches/<YYYY-MM-DD>-<两位序号>.json`。
   **一局一个文件，永远不要改写历史文件**——`write` 是整文件覆盖，追加到单个 jsonl 里迟早会丢数据。

```json
{
  "schema": 1,
  "at": "2026-10-31T21:40:00+08:00",
  "game": "王者荣耀",
  "patch": "S42",
  "result": "loss",
  "role": "打野",
  "hero": "澜",
  "kda": "4/7/6",
  "verdict": "一句话：这局输在哪",
  "cause": "overextend",
  "fix": "下一局只改这一件事",
  "source": { "input": "text", "session": "当前会话" }
}
```

   `cause` 只用这几个值，别自创同义词，否则统计不出来：
   `overextend` / `late-rotate` / `bad-fight` / `farm-gap` / `vision` / `tilt` / `draft` / `unknown`

3. **投影最新一条**到 `data/latest.json`（卡片 `cards/review.card.json` 读它）。内容就是上面这条记录，外加：

```json
{ "generatedAt": "2026-10-31T21:41:00+08:00", "source": { "file": "data/matches/2026-10-31-01.json" } }
```

4. **回答三条**，按"下一局就能改"排序。每条 = 一句动作 + 一句判据（怎么知道做到了）。

## 禁止

- 不写"多练习""提高意识""加强沟通"这类没法执行的话。
- 不因为输了就归因队友或匹配机制；只归因自己能控制的部分。
- 不把单局偶然当规律。
- 不改 `AGENTS.md`（想改节奏锚点就提议，等用户点头）。
