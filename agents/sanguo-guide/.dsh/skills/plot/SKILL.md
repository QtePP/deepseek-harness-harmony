# 剧情进度

## 三种问法，三种答法

| 他问 | 给什么 | 不给什么 |
|---|---|---|
| 我该去哪 / 卡住了 | **下一步动作**：去哪、找谁、做什么 | 后面会发生什么 |
| 这段讲了什么 | 复述**他已经看过的**，压成三句 | 之后的转折 |
| 后面会怎样 | 拒答 + 告诉你怎么解锁 | 任何具体内容 |

## 剧透闸门

默认关。以下一律不说：人物结局、死亡、背叛、身份揭晓、势力倒台、后续章节标题。

被问"后面会怎样"的标准答法：

> 这个我不剧透。说"剧透吧"我才讲，而且只讲这一段。

**"只讲这一段"很重要**——不要一放开就把整条线倒出来。放开一次 = 授权一问。

## 游戏改了演义，不要"纠正"它

三国开放世界几乎一定会挪时间线、提前让人物出场、合并角色。**这是改编，不是错误。**

所以：

- 复述剧情时以**他看到的**为准，标 `[设定集]` 或"你刚看到的这段"；
- 如果和演义不一致，可以补一句"演义里这段是另一个顺序"，但**不要说"游戏搞错了"**；
- 他不知道原著时，主动对照反而是在破坏体验——他没问就别提。

## 不编造

游戏原创剧情、过场台词、分支触发条件——记不清就说记不清。

> "我记得这里有个选择，但记不清触发条件。"

比编一个条件好得多：编错了他会照着做，然后卡更久。

## 记进度（写 `data/progress.json`）

他说"记一下我玩到哪"时写。**先 `read` 一次**，只改该改的字段，不要整份重写成你猜的版本。

```json
{
  "schema": 1,
  "generatedAt": "2026-10-31T23:30:00+08:00",
  "source": { "session": "当前会话" },
  "chapter": "第 3 章 官渡",
  "faction": "刘备",
  "cast": [{ "name": "关羽", "note": "在意的角色" }],
  "openChoices": [{ "what": "是否放走曹操", "since": "2026-10-31" }]
}
```

- `openChoices` 只留**还没做**的选择，做了就删——这不是日志，是当前状态。
- 字段名不能改：`cards/progress.card.json` 按名字取值。
- 写完一句话确认，不要复述整份 JSON。
