# 说书人 · story-guide

三国 / 水浒题材的剧情向 Agent。你玩着剧情游戏，想问"这人是谁""这段讲了什么""选哪个"。

这类题材有一个别人看不见的坑：**同一个故事有三层版本**——小说、正史、游戏改编。
模型最常见的错误不是不知道，而是**把三层混着说**，而且混完听起来还很顺。

所以这个 pack 的核心不是"知道得多"，是**每条都标清是哪一版**。

## 长什么样

```
你：温酒斩华雄是真的吗
它：演义里是关羽，正史里是孙坚。
    [演义] 关羽温酒未凉即斩华雄，是小说加的细节。
    [正史] 《三国志》记"枭其都督华雄"，动手的是孙坚。
    本作怎么改的我不确定，你打到那一段看。
```

```
你：后面关羽会怎样
它：这个我不剧透。
    你要是想听，说"剧透吧"，我只讲这一段。
```

```
你：这谁啊（说的"孟德"）
它：孟德就是曹操。
    [演义][正史] 同一人：名曹操，字孟德，小名阿瞒。
    本作要是另有称号，你告诉我我按本作的叫。
```

注意第一条：它没有简单回答"真的"或"假的"，而是**把三层摆开**——因为问"是不是真的"的人，
真正想知道的就是"我在哪一层"。

注意第三条：它先用**用户自己的称呼**回答，再补学名。反过来会让人以为在说别人。

## 三个机制

### 1. 三源标注（不许关）

| 标签 | 含义 |
|---|---|
| `[演义]` | 小说情节（《三国演义》/《水浒传》） |
| `[正史]` | 《三国志》及裴注、《宋史》等 |
| `[本作]` | 你正在玩的这款游戏的原创设定 |

归不进去就写"这条我记不清是哪一版"——**不许用"据说""相传"糊过去**。

`sources` 技能里带了一张对照表（温酒斩华雄、草船借箭、空城计、三英战吕布、刮骨疗毒、
周瑜气量、宋江人马），每条都标了演义/正史两列，`本作` 那列永远留空——
**游戏怎么改的，只有玩到那一步的人知道**，模型不该猜。

### 2. 剧透闸门

默认关闭。人物结局、死亡、背叛、身份揭晓、势力倒台、后续章节标题——一律不说。
被问就答"这个我不剧透，说'剧透吧'我才讲，而且只讲这一段"。

**"只讲这一段"是关键**：放开一次 = 授权一问，不是从此不设防。

### 3. 不摆关系网

只答直接关系（父子 / 兄弟 / 师徒 / 主从 / 仇怨）。"他表哥的岳父是某某的对头"这种话，
等于把后面的剧情提前讲了，而且链条越长越容易编。

## 为什么不做"考据党"

用户玩的是**演义题材游戏**，演义才是这个世界的设定。用正史去否定游戏，是在拆台不是帮忙。

所以 `sources` 技能里明写：不要说"其实历史上不是这样的"，
要说"演义里是这样，正史里是那样，你玩的这版可能又不一样"——
把三层摆清楚，让他自己选信哪个。

## 怎么装（两条路，都不用改代码）

**路 A（只需要手机）**：新建项目 → 把 `BOOTSTRAP.md` 里 `---` 之间整段粘进对话 →
模型用 `write` 落盘 → 一次性问你作品、游戏、进度、阵营。

**路 B（开发者）**：DevEco Device File Browser → `.../haps/entry/files/workspaces/<projectId>/`
→ 上传本目录**内容**。上传后形状：

```
workspaces/<projectId>/
  AGENTS.md
  agent.json
  cards/progress.card.json
  .dsh/skills/who-is/SKILL.md
  .dsh/skills/plot/SKILL.md
  .dsh/skills/choice/SKILL.md
  .dsh/skills/sources/SKILL.md
  data/
```

## 两条会静默失效的坑

1. **技能目录锚定 git 根，不是 cwd。** `findProjectRoot()` 向上找 `.git`，找到就用它当 project root。
   设备沙箱没有 `.git` 所以正常；**在仓库里直接测这个 pack 一定不生效**，桌面验证要先拷到仓库外。
2. **热路径不要调工具。** 配置和"我玩到哪"都在 `AGENTS.md`（会话建立时注入）。
   参考材料（`sources` 的三源表）才放技能里按需加载——**状态放 AGENTS.md，资料放技能**。

## 换成水浒

改 `AGENTS.md` 两处：作品行改成「水浒传」，热知识区换成人名/绰号。

技能不用动，但 `sources` 表要补水浒条目——已有的那条「宋江人马：小说 108 将，正史记载
三十六人」可以直接用。其余条目（招安、征方腊）史载零散且有争议，**标"未确认"而不是写结论**。

## 目录

| 路径 | 作用 | 谁改 |
|---|---|---|
| `AGENTS.md` | 人格 + 配置 + 输出契约 + 剧透档位 + 热知识 | 用户（改行为要确认） |
| `agent.json` | Agent 元数据 | 用户 |
| `.dsh/skills/who-is/` | 人物与关系：消歧 + 三源 | 用户 |
| `.dsh/skills/plot/` | 剧情进度：三种问法三种答法 + 写 `data/progress.json` | 用户 |
| `.dsh/skills/choice/` | 选择分支：只说影响类别，不说后果 | 用户 |
| `.dsh/skills/sources/` | 原著对照：三源表 + 最容易混的四类 | 用户 |
| `cards/progress.card.json` | 「说到哪了」卡片投影（**应用内还没有渲染器**） | 用户 |
| `data/progress.json` | 章节 / 阵营 / 未做决定 / 在意的角色 | Agent |

## 已知没做

- **卡片还看不见**：没有 CardRenderer，`progress.card.json` 是给 S1 的契约；数据链路是真的。
- **`data/progress.json` 首次使用前不存在**，卡片应隐藏而不是显示空值。
- **三源表只有 7 条**：这是种子，不是全库。遇到表外的问题，它应该说"未确认"而不是硬答——
  如果它开始硬答，说明 `sources` 技能被绕过了。
- **没有版本/卡池**：剧情向游戏不需要，换到抽卡游戏要另加。

## 验收（装完自己点四下）

1. 发「温酒斩华雄是真的吗」→ 必须出现 `[演义]` 和 `[正史]` 两种标注，且说法不同。
2. 发「后面 XX 会怎样」→ 拒答，并告诉你怎么解锁。
3. 发「这谁啊」用一个字或绰号 → 先按你的叫法确认，再补学名。
4. 发「记一下我玩到官渡了」→ `data/progress.json` 出现。

第 1 条是核心：**它必须把三层分开，而不是给你一个听着很顺的答案。**
